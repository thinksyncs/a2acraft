# 機能要件書（FRD）　村で出会ったチャットからタスクを生む

## ユーザー体験

別々のチャットが村で出会い、それぞれが知っていることを持ち寄る。二人が具体的な次の仕事に合意すると、その場で担当者つきのTODOが生まれ、担当者が取りかかる。利用者は後から「誰と誰の、どの発言からこの仕事が生まれたか」と実行結果を確認できる。

たとえば、花壇の観察を続けている住民が「朝はまだ土が湿っていた」と話す。水やりを計画している住民が「曜日と天候ごとの観察表を作ろうか」と応じる。最初の住民が同意すれば、担当者が表の下書きを作り、TODOに結果が残る。近況を話しただけなら、会話の記録だけが残る。

## 村での操作

- 利用者は村の「この辺りの会話」→「住民の出会い」→「出会いからタスクを作る」で自動対話を有効にする。設定は端末のアプリデータに保存する。初期状態はオフ。有効にする前に、二人の会話を参照すること、Codexの利用枠を使うこと、合意したTODOを自動実行することが分かるようにする。
- 表示中の村で、異なる二つのチャットに対応する人物が離れた位置から接触したときに開始する。隊の所属は問わない。同じ人物の重複描画、画面の再表示、接触し続ける二人は、新しい出会いとして数えない。
- 立ち話の引用表示、利用者が自分で住民に話しかける操作、自動対話は個別に使える。デモの人物から実アカウントへの送信は発生しない。

## 対話とタスクの成立

1. アプリは参加資格と実行状態を確認し、二つのチャットIDにひもづく出会いを記録する。会話は同時に1組までとする。
2. 一人目が自分の話題から話しかけ、二人目はその発言を受けて自分の視点から応答する。発言は各人の立場で別々のCodexターンとして生成し、話者と本文を会話順に残す。
3. 二人目は、成果物と担当が具体的なら仕事を一つ提案できる。提案を受けた一人目が同意した場合のみ、参加者の一方を担当にしたTODOを作る。拒否、雑談、不正な形式の応答からは仕事を開始しない。
4. TODOには出会いのID、参加者、件名、実施内容、担当を残す。既存のTODO実行経路を使い、実行可能なら個別の承認操作を挟まず開始する。会話が終わったことと、タスクが完了したことは別々に表示する。
5. 新しい出会いは村の地図上に知らせ、話者と直近の発言を読めるようにする。そこから対話の記録や該当するTODOを開き、進捗と成果を確認できる。生成後に実行を開始できない場合もTODOを残し、通常のTODO画面から扱えるようにする。

## 許可範囲と再開

- 対話のたびに接続、利用枠、参加チャットの有効性を確認する。参加対象は通常のローカルチャット。開発プロジェクトの担当や、外部から取り込んだ履歴は対象外とする。各発言は話者自身の直近の本文2件（各500文字まで）、相手の名前、それまでの対話を使う。添付、ツール記録、他のチャット履歴をまとめて渡さない。
- タスクは通常のTODOとして保存し、回答本文で成果を返す。提供された情報からの比較、設計案や文案の作成が対象となる。生成には読み取り専用の一時スレッドを使い、ファイル変更や外部送信の権限を付与しない。
- 提案は1回の出会いに1件まで。二人のIDの順序にかかわらず同じ組として扱う。同じ組の次の対話まで30分、村全体の次の対話まで最低1分空ける。再通知、複数画面からの同時通知や再起動で二重にTODOを作らない。
- 村には直近64件の出会いを残す。生成したTODOには、元の参加者名と会話を別に保存し、村の履歴から古い出会いが消えた後も由来をたどれるようにする。
- 利用者が設定をオフにしたら新たな対話や自動着手を止める。実行済みか判定できないターンやTODOを、再起動を理由に再送しない。記録から中断した場所が分かるようにする。

## 受け入れ条件

| 確認する場面 | 期待する結果 |
| --- | --- |
| オフの状態で接触、またはサンプルの村で接触 | モデル呼び出しと実TODO作成は0件 |
| 有効な2人が近づいて接触 | 一人目の実際の発言が二人目への入力に入り、話者別に記録される |
| 二人目が具体案を出し一人目が同意 | 新規TODOが1件でき、担当が実行。成果は対応するTODOで読める |
| 雑談、拒否、壊れた応答 | 自動実行は0件。会話の結果または停止理由を確認できる |
| 重なったまま、順序を逆に再通知、画面を再表示 | 同じ接触で再度の対話やTODOが生まれない |
| 発言中に無効化、切断、利用枠不足、アプリ再起動 | 新しい仕事を勝手に開始せず、保存できた記録は残る |

日本語・英語の実際の村画面から同じ操作を行えること。自動テストでは架空の会話とCodexのプロトコル代替を使い、画面の接触判定、モデルへの入力、サーバーのTODO保存と完了結果を検査する。実アカウントでの受け入れでは、参加者の発言と生成したTODOを照合する。
